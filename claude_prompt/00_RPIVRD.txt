R-P-I-V-R-D
Read -> Plan -> Implement -> Verify -> Review -> Deliver

REPO / SYSTEM: [REPO_OR_SYSTEM]   e.g., the PDAC agentic curation pipeline (pipeline/graph.py, nodes.py, state.py)
GOAL: [GOAL]                      e.g., Make run_pipeline.py skip a patient whose thread_id is already checkpointed as finished
QUESTION / TASK: [QUESTION]       e.g., Why did --limit 20 re-run the 10 patients already completed under --limit 10?
CONSTRAINTS: [CONSTRAINTS]        e.g., no changes to the checkpoints.sqlite schema; must keep working with SqliteSaver

Use this as the default loop for anything beyond a trivial change. Each
stage below maps to a specific habit an interviewer or reviewer is
checking for, not just a step to complete.

READ
Inspect the repository and relevant files first. Do not modify anything yet.
Identify:
- current workflow
- main entry point(s)
- files/components related to [GOAL]
- inputs, outputs, state, APIs, data sources, external dependencies
- tests and run commands
- confirmed facts vs assumptions vs unknowns

PLAN
Propose the smallest reasonable solution.
Include:
- likely root cause or implementation approach
- exact files to change
- what not to change
- edge cases / risks
- validation plan
Ask only questions that materially affect the solution.
Do not implement yet.

IMPLEMENT
After I approve the plan, implement only the agreed scope.
Reuse existing patterns.
Avoid unrelated refactors or unnecessary dependencies.
If scope must expand, stop and explain why first.

VERIFY
Run the most relevant tests/checks.
Use representative inputs.
Show actual results.
Mark anything not verified.

REVIEW
Review the diff for:
- logic bugs
- regression risk
- bad assumptions
- null/malformed inputs
- security/privacy
- retry/timeout/idempotency
- unnecessary complexity
- missing tests

DELIVER
Return:
1. What you found
2. What you changed
3. How you verified it
4. Remaining risks / unknowns
5. Recommended next step

Strong framing to use out loud:
"Before I change anything, I want to understand the expected workflow,
reproduce the discrepancy, identify the source of truth, and define how
we will know the fix worked."
