MERGE CONFLICTS — PRACTICAL WORKFLOW

WHEN THEY HAPPEN:
Two branches changed overlapping lines.


Scenario:
main changed src/claim_router.py
your branch also changed src/claim_router.py


----------------------------------------
START
----------------------------------------

git merge main

Git may report:
CONFLICT (content): Merge conflict in src/claim_router.py


----------------------------------------
INSPECT
----------------------------------------

git status

Open src/claim_router.py.

You may see:

<<<<<<< HEAD
route = classify_claim(claim)
=======
route = route_claim_by_payer(claim)
>>>>>>> main


----------------------------------------
RESOLVE
----------------------------------------

Decide what final code should actually be.

For example:

route = route_claim_by_payer(claim)
route = validate_route(route)


Remove:
<<<<<<<
=======
>>>>>>>


----------------------------------------
MARK RESOLVED
----------------------------------------

git add src/claim_router.py


----------------------------------------
VERIFY
----------------------------------------

Run relevant test:

pytest tests/test_claim_router.py

Review staged result:

git diff --staged


----------------------------------------
FINISH MERGE
----------------------------------------

git commit


----------------------------------------
ABORT IF YOU ARE NOT READY
----------------------------------------

git merge --abort


For rebase:
git rebase --abort


IMPORTANT:
Do not resolve conflicts by blindly choosing "ours" or "theirs."
Understand the intended behavior.
