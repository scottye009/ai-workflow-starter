UNDO — CHOOSE BASED ON WHAT YOU WANT TO KEEP

ASK FIRST:
Do I want to keep the file changes?
Do I want to keep the commit in history?


----------------------------------------
CASE 1: DISCARD UNSTAGED CHANGES IN ONE FILE
----------------------------------------

Scenario:
You experimented in src/router.py and want the original version back.

git restore src/router.py

WARNING:
Uncommitted changes in that file are lost.


----------------------------------------
CASE 2: UNSTAGE BUT KEEP FILE CHANGES
----------------------------------------

Scenario:
You staged secrets.env accidentally.

git restore --staged secrets.env

File remains unchanged on disk.


----------------------------------------
CASE 3: UNDO LATEST COMMIT BUT KEEP CHANGES STAGED
----------------------------------------

git reset --soft HEAD~1

Use when:
Commit structure/message was wrong,
but you want all code changes preserved.


----------------------------------------
CASE 4: UNDO LATEST COMMIT AND KEEP CHANGES UNSTAGED
----------------------------------------

git reset HEAD~1

Changes remain in files.


----------------------------------------
CASE 5: UNDO A COMMIT THAT WAS ALREADY SHARED
----------------------------------------

git revert a31bc55

This creates a NEW commit that reverses a31bc55.

Use this for shared history.


----------------------------------------
PREFERRED RULE
----------------------------------------

Local/private history:
reset may be okay.

Already pushed/shared history:
prefer revert.


AVOID:
git reset --hard HEAD~1

unless you intentionally want to destroy local changes.
