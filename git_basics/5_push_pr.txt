PUSH / PREPARE FOR PR

WHEN TO USE:
Your local branch is ready to share.


----------------------------------------
FIRST PUSH
----------------------------------------

Branch:
fix/payment-posting-duplicate

Command:
git push -u origin fix/payment-posting-duplicate

-u means:
Future pushes can just use:

git push


----------------------------------------
BEFORE PUSHING
----------------------------------------

Run:

git status
git diff main...HEAD
git log main..HEAD --oneline

Check:
- only intended files changed
- no .env
- no tokens
- no customer data
- no debug output
- tests pass


----------------------------------------
AFTER PUSHING
----------------------------------------

Typical PR description:

Problem:
Retries could post the same payment twice.

Root cause:
The write path retried after timeout without checking whether the posting had already succeeded.

Change:
Added an idempotency key and status check before retry.

Validation:
Added regression tests for timeout + retry and duplicate request.

Risk:
Existing payment posting path unchanged for first-time requests.


----------------------------------------
FORCE PUSH
----------------------------------------

Avoid:
git push --force

If absolutely necessary and team policy permits:
git push --force-with-lease

Why safer:
It refuses to overwrite remote work you did not know about.
