STATE DESIGN

Good state should contain only what later steps need.

Typical fields:
- run_id / thread_id
- input identifiers
- source data references
- normalized inputs
- intermediate results
- final result
- status
- needs_review
- errors

Prefer explicit fields over one giant dict.

Example:
class State(TypedDict, total=False):
    claim_id: str
    payer: str
    denial_text: str
    category: str
    confidence: float
    needs_review: bool
    status: Literal["pending", "ok", "error"]
    errors: list[str]

Guidelines:
- store IDs, not duplicate huge objects
- distinguish source data from derived data
- make review/error states explicit
- avoid recomputing the same transformation in multiple nodes
- if dates are normalized, normalize once and carry the normalized value
